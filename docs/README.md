##  2. Исследование предметной области

### 2.1. Почему не библиотеки-обёртки?
При изучении готовых решений мы обнаружили, что большинство туториалов предлагают использовать SDK-обёртки. Однако задание требовало реализации **«с нуля»**. Мы выбрали прямую работу с REST API через `requests`, так как это:
- Даёт полный контроль над HTTP-запросами, заголовками и кодами ответов.
- Позволяет наглядно увидеть структуру JSON-ответов Telegram и понять, как работают веб-интерфейсы.
- Соответствует академическому требованию понимания протокола, а не просто вызова готовых функций.

### 2.2. Long Polling vs Webhooks
Мы реализовали **Long Polling** (`getUpdates`), так как для учебного проекта это решение:
- Не требует выделенного сервера с публичным IP-адресом.
- Проще в отладке на локальных машинах разработчиков.
- Не требует настройки SSL-сертификатов и доменов.
Сервер Telegram удерживает соединение до `timeout` секунд или до появления нового сообщения, что снижает нагрузку по сравнению с простым циклическим опросом.

### 4.2. Реализация HTTP-обёртки (`api.py`)

На этом этапе мы создаём функции для общения с сервером Telegram. Вместо того чтобы писать HTTP-запросы в каждом месте кода, мы выносим их в отдельный модуль `api.py`. Это делает код чище и удобнее для поддержки.

Нам нужны две основные функции: одна для получения сообщений от пользователей, другая для отправки ответов.

```python
import requests
from config import BASE_URL

def get_updates(offset, timeout):
    """
    Получение новых сообщений от Telegram (Long Polling).
    Запрашивает у сервера обновления начиная с определённого ID.
    """
    # Формируем параметры запроса
    params = {"offset": offset, "timeout": timeout}
    
    response = requests.get(f"{BASE_URL}/getUpdates", params=params)
    
    # Если сервер вернул ошибку (неверный токен, 404, 500), сразу останавливаемся
    response.raise_for_status()
    
    return response.json()


def send_message(chat_id, text, reply_markup=None):
    """
    Отправка текстового сообщения пользователю.
    Поддерживает обычное текстовое сообщение и клавиатуру с кнопками.
    """
    # Собираем обязательные данные
    data = {"chat_id": chat_id, "text": text}

    if reply_markup:
        import json
        data["reply_markup"] = json.dumps(reply_markup)

    response = requests.post(f"{BASE_URL}/sendMessage", json=data)
    
    # Проверяем на ошибки сети или API
    response.raise_for_status()
    
    return response.json()
```

#### Как это работает и почему так сделано:
- `get_updates()` использует метод GET. Он «стучится» к Telegram и спрашивает: 
«Есть что-то новое?». Сервер держит соединение открытым до тех пор, пока не появится сообщение или не истечёт время timeout. 
Это называется Long Polling — экономит ресурсы по сравнению с постоянным опросом.
- `send_message()` использует метод POST. Мы передаём данные (текст, кнопки) на сервер, поэтому нужен именно POST-запрос.
- `response.raise_for_status()` — критически важная строка. Без неё бот мог бы молча игнорировать 
ошибки (например, неверный токен или отключение интернета). Эта команда гарантирует, что при любой проблеме программа сразу сообщит об ошибке.
- `json.dumps(reply_markup)` — Telegram API принимает клавиатуру строго в виде JSON-строки. Мы 
явно преобразуем словарь в строку, чтобы сервер гарантированно её понял.
- `return response.json()` превращает сырой ответ сервера в обычный словарь Python. Дальше в коде мы сможем обращаться к полям как `update["message"]["text"]`, а не парсить текст вручную.

### 4.3. Хранилище состояний игроков (bot.py)
Теперь нам нужно решить главную проблему: как боту «помнить» каждого игрока? Когда пользователь нажимает кнопку второй раз, бот должен знать, какое у него было настроение у прохожего в первый раз, сколько листовок он уже раздал и т.д.
Для этого мы создаём словарь players, который хранит прогресс всех пользователей.

Глобальный словарь для хранения прогресса всех игроков
Ключ: chat_id пользователя (уникальный номер в Telegram)
Значение: словарь с данными игрока (настрой NPC, статистика, квесты)
Данные хранятся в оперативной памяти, пока скрипт запущен

`get_or_init_player` возвращает профиль игрока или создаёт новый, если игрок пишет впервые.
    
Эта функция решает две задачи:
1. Если игрок уже есть в словаре — просто возвращаем его данные
2. Если игрока нет — создаём «чистый лист» с начальными значениями
    
Это позволяет боту «помнить» каждого пользователя в рамках сессии.

```python
players = {}

# Структура клавиатуры: список списков = строки кнопок
MAIN_KEYBOARD = {
    "keyboard": [
        [{"text": "📋 Взять квест"}, {"text": "🎁 Раздать листовку"}],
        [{"text": "😊 Улыбнуться"}, {"text": "😤 Надавить"}],
        [{"text": "📊 Статистика"}]
    ],
    "resize_keyboard": True,
    "one_time_keyboard": False
}

def get_or_init_player(chat_id: int) -> dict:

    # Проверяем, есть ли уже этот игрок в словаре
    if chat_id not in players:
        players[chat_id] = {
            "npc_state": "НЕЙТРАЛЬНОЕ",
            # Словарь статистики для достижений и отчётов
            "stats": {
                "given": 0,           # сколько листовок роздано
                "refusals": 0,        # сколько отказов получено
                "smiles": 0,          # сколько раз улыбнулись
                "interactions": 0,    # всего взаимодействий
                "fatigue": 0          # уровень усталости (0-100%)
            }, 
            "quest_active": False
        }
    
    return players[chat_id]
```

Мы используем обычный словарь `players` для хранения прогресса всех пользователей. 
Ключ — `chat_id` из Telegram, значение — словарь с настроением прохожего, статистикой и флагом квеста. 
Это позволяет боту «помнить» каждого игрока в рамках одной сессии без базы данных.


Telegram требует, чтобы кнопки передавались как список списков: каждый внутренний список — 
это отдельная строка на экране. `"resize_keyboard": True` подстраивает размер кнопок под ширину экрана телефона,
а `"one_time_keyboard": False` оставляет клавиатуру видимой после нажатия.

Функция `handle_message` выступает центральным диспетчером бота. Её главная задача — принять «сырое» обновление от сервера Telegram,
отфильтровать технический шум, извлечь команду пользователя и направить выполнение программы в нужный блок игровой логики. Вся работа построена на последовательной проверке 
условий через конструкцию `if/elif`, которая работает как строгий маршрутизатор.

Сначала функция выполняет валидацию входящих данных. Telegram API может присылать не только текстовые сообщения, но и системные уведомления, обновления о 
редактировании чата, фото или стикеры. Условие `if "message" not in update or "text" not in update["message"]` мгновенно прерывает выполнение, если пришло не 
текстовое событие. 


После фильтрации извлекается уникальный идентификатор чата `chat_id` и сам текст сообщения, очищенный от пробелов по краям. Сразу за этим следует вызов `get_or_init_player`. Этот шаг гарантирует, что под каждым 
`chat_id` в оперативной памяти уже существует словарь с данными игрока. Если пользователь пишет впервые — профиль создаётся «на лету» с нулевой статистикой и нейтральным настроением прохожего. Если игрок уже взаимодействовал
с ботом — функция просто возвращает ссылку на его существующие данные. 

Далее начинается сама маршрутизация. Конструкция `if/elif` последовательно сверяет текст сообщения с известными триггерами. Разберём ключевые ветки подробнее:


**Ветка `/start`** срабатывает при первом запуске или ручном вызове команды. Здесь бот не меняет игровые параметры, а выполняет настройку интерфейса: формирует приветственный текст и передаёт его в функцию отправки вместе с объектом клавиатуры. 
Параметр `reply_markup` заставляет Telegram отрисовать 
постоянную панель кнопок внизу экрана. Это точка входа, которая подготавливает окружение для дальнейшей игры.


**Ветка «🎁 Раздать листовку»** содержит самую сложную логику. При совпадении условия код фиксирует тип действия и передаёт текущее настроение прохожего в модуль конечного автомата. 
Тот возвращает эмоциональную реакцию и новое состояние. Затем происходит интеллектуальная проверка успеха: вместо привязки к формальному статусу, система сканирует текст реакции на 
наличие ключевых слов («спасибо», «возьму», «ладно», «молодец»). Если совпадение найдено — действие считается успешным, счётчик розданных листовок увеличивается, а усталость растёт стандартным шагом.
Если ключевых слов нет — фиксируется отказ,
и в статистику добавляется отдельный счётчик провалов. В завершение ветки бот отправляет игроку реакцию прохожего и обязательно возвращает клавиатуру, чтобы интерфейс оставался активным.


**Ветка `/next_day`** выполняет роль инструмента сброса. Она не взаимодействует с NPC и не считает статистику, а принудительно обнуляет флаг активного квеста и возвращает настроение прохожего в исходное
состояние «НЕЙТРАЛЬНОЕ». Это позволяет игроку начать новую игровую сессию без перезапуска всего процесса Python.
Блок else работает как страховочная сеть. Он срабатывает, если пользователь ввёл произвольный текст, не совпадающий ни с одной кнопкой или служебной командой. Вместо молчаливого игнорирования бот выводит вежливое предупреждение об использовании интерфейса и принудительно отправляет клавиатуру заново. Это решает частую проблему мобильных клиентов Telegram, где панель кнопок иногда скрывается после сворачивания приложения, и возвращает пользователя в рабочее русло.
        

#### Как это работает на практике:
Когда пользователь впервые нажимает `/start`, функция `get_or_init_player` создаёт ему профиль с нулевыми значениями. 
Когда он нажимает кнопку второй раз, функция находит его chat_id в словаре и возвращает уже заполненные данные.

**Важное ограничение:** Данные хранятся в оперативной памяти процесса Python. Если перезапустить бота (выключить и включить скрипт), 
все данные сотрутся. Для постоянного хранения нужна база данных (SQLite, PostgreSQL) или JSON-файл, но для учебной практики текущего решения достаточно.

```python
        "push": ["Убегает со всех ног! ‍♀️", "Зовёт на помощь! 🆘", "Полный игнор! 🙈"]
    }
}

def npc_react(current_state, action):
    reactions_list = REACTIONS.get(current_state, {}).get(action, ["Прохожий не понимает действие."])
    text = random.choice(reactions_list)

    if action == "flyer":
        if current_state == "НЕЙТРАЛЬНОЕ":
            new_state = "ДРУЖЕЛЮБНЫЙ" if random.random() > 0.3 else "НЕЙТРАЛЬНОЕ"
        elif current_state == "ДРУЖЕЛЮБНЫЙ":
            new_state = "РАЗДРАЖЁННЫЙ" if random.random() > 0.7 else "ДРУЖЕЛЮБНЫЙ"
        elif current_state == "РАЗДРАЖЁННЫЙ":
            new_state = "ИЗБЕГАЕТ" if random.random() > 0.5 else "РАЗДРАЖЁННЫЙ"
        else:
            new_state = "ИЗБЕГАЕТ"
    elif action == "smile":
        if current_state in ["НЕЙТРАЛЬНОЕ", "ДРУЖЕЛЮБНЫЙ"]:
            new_state = "ДРУЖЕЛЮБНЫЙ"
        elif current_state == "РАЗДРАЖЁННЫЙ":
            new_state = "НЕЙТРАЛЬНОЕ" if random.random() > 0.6 else "РАЗДРАЖЁННЫЙ"
        else:
            new_state = "ИЗБЕГАЕТ"
    elif action == "push":
        if current_state == "НЕЙТРАЛЬНОЕ":
            new_state = "РАЗДРАЖЁННЫЙ"
        elif current_state == "ДРУЖЕЛЮБНЫЙ":
            new_state = "РАЗДРАЖЁННЫЙ"
        elif current_state == "РАЗДРАЖЁННЫЙ":
            new_state = "ИЗБЕГАЕТ"
        else:
            new_state = "ИЗБЕГАЕТ"
    else:
        new_state = current_state

    return text, new_state
```

#### Разбор логики:
- Словарь `REACTIONS` хранит списки фраз для каждой комбинации «состояние + действие». `random.choice()` выбирает одну случайно, убирая механическое повторение.
- Функция `npc_react` сначала берёт реакцию, потом вычисляет новое состояние. Переходы управляются `random.random()` > X,
где X — порог вероятности. Например, при раздаче листовок в состоянии НЕЙТРАЛЬНОЕ есть 70% шанс стать ДРУЖЕЛЮБНЫМ
(`random.random()` возвращает число от 0.0 до 1.0, условие > 0.3 выполняется в 70% случаев).


#### Генератор квестов 
Модуль отвечает за создание ежедневных заданий. Чтобы игра не надоедала, мы комбинируем 
базовые цели со случайными погодными/временными модификаторами, которые динамически меняют награду.

```python
import random

QUESTS = [
    {"text": "Раздай 5 листовок у метро", "base_reward": 10},
    {"text": "Улыбнись каждому 3-му прохожему", "base_reward": 5},
    {"text": "Избегай полиции в парке", "base_reward": 15},
    {"text": "Поговори с незнакомцем о погоде", "base_reward": 8}
]

MODIFIERS = [
    {"condition": "🌧 Дождь", "text": "Листовки мокнут, эффективность −30%", "mult": 0.7},
    {"condition": "☀️ Солнечно", "text": "Люди в настроении, +20% к успеху", "mult": 1.2},
    {"condition": "🌆 Вечер пятницы", "text": "Все спешат, но открыты к общению", "mult": 1.0}
]

def generate_daily_quest():
    quest = random.choice(QUESTS)
    mod = random.choice(MODIFIERS)
    reward = int(quest["base_reward"] * mod["mult"])
    return f"📋 Задание: {quest['text']}\n{mod['condition']} — {mod['text']}\n Награда: {reward} очков"
```

#### Как работает генерация:
- `QUESTS` — пул базовых заданий с фиксированной наградой.
- `MODIFIERS` — список условий, влияющих на атмосферу и множитель награды (`mult`).
- `generate_daily_quest()` случайно выбирает по одному элементу из каждого списка, перемножает базовую награду на модификатор 
- (`int(quest["base_reward"] * mod["mult"])`) и собирает итоговую строку через 
f-форматирование. Это даёт 4×3 = 12 уникальных комбинаций без дублирования кода и жёсткой привязки к контексту.


### Трекер статистики и достижений (stats_tracker.py)
Этот модуль агрегирует действия игрока, считает усталость и
проверяет условия разблокировки наград. Вся логика построена на словарях 
и функциях высшего порядка.

```python
# Условия достижений
ACHIEVEMENTS = {
    "first_step": {"cond": lambda s: s["given"] >= 1, "title": "🥉 Первый шаг"},
    "smile_master": {"cond": lambda s: s["smiles"] >= 5, "title": "😎 Мастер улыбки"},
    "relentless": {"cond": lambda s: s["given"] >= 20, "title": " Неутомимый курьер"},
    "survivor": {"cond": lambda s: s["interactions"] >= 30 and s["fatigue"] > 80, "title": " Выживший"}
}

def update_stats(stats, action, success=True):
    if action == "flyer" and success: stats["given"] += 1
    if action == "refusal": stats["refusals"] += 1
    if action == "smile": stats["smiles"] += 1
    if action == "push":
        stats["pushes"] = stats.get("pushes", 0) + 1  # Счётчик надавливаний
    stats["interactions"] += 1
    stats["fatigue"] = min(100, stats["fatigue"] + 5)
    return stats

def get_daily_summary(stats):
    """Генерирует итоговую сводку"""
    unlocked = [a["title"] for a in ACHIEVEMENTS.values() if a["cond"](stats)]
    ach_text = "\n " + ", ".join(unlocked) if unlocked else "\n🏆 Достижений пока нет"

    return (f"📊 Итоги дня:\n"
            f" Раздано: {stats['given']} | ❌ Отказов: {stats['refusals']}\n"
            f"😊 Улыбок: {stats['smiles']} | 😴 Усталость: {stats['fatigue']}%{ach_text}")
```

#### Ключевые механизмы:
- `ACHIEVEMENTS` использует лямбда-функции (`lambda s: s["given"] >= 1`) для декларативного описания условий. 
Это позволяет добавлять новые достижения одной строкой, не меняя логику проверки.
- `update_stats` инкрементирует счётчики в зависимости от action. Усталость (fatigue) растёт на 5% за каждое действие, но ограничена min(100, ...) — это классический «потолок» (clamping), который не даёт значению уходить в бесконечность.
- `get_daily_summary` фильтрует достижения через list comprehension: 
`[a["title"] for a in ACHIEVEMENTS.values() if a["cond"](stats)]`. Если список не пуст — форматирует их через `", ".join()`, иначе выводит заглушку. Итоговая строка собирается в один f-string для отправки в Telegram.


### 4.5. Точка входа и «двигатель» бота (`main.py` и `run_bot`)

Эти два фрагмента — финальный шаг сборки. `main.py` служит стартовой точкой приложения, а функция `run_bot()` — его «сердцем», которое обеспечивает непрерывную работу, опрос сервера Telegram и обработку событий в реальном времени. Именно здесь разрозненные модули (`api`, `bot`, `game/`) объединяются в единый работающий процесс.

#### Точка входа (`main.py`)

```python
from bot import run_bot

if __name__ == "__main__":
    run_bot()
```

```python
def run_bot():
    last_update_id = 0
    print("🤖 Бот запущен. Нажмите Ctrl+C для остановки.")
    while True:
        try:
            updates = get_updates(offset=last_update_id, timeout=POLLING_TIMEOUT)
            if updates.get("ok") and updates.get("result"):
                for update in updates["result"]:
                    last_update_id = update["update_id"] + 1
                    handle_message(update)
        except Exception as e:
            print(f"⚠️ Ошибка: {e}")
        time.sleep(1)
```

1. `last_update_id`: Telegram присылает сообщения пакетами. Если не запоминать, какое сообщение мы уже обработали, бот будет бесконечно перечитывать одно и то же. last_update_id хранит ID последнего обработанного события. После обработки мы увеличиваем его на +1, чтобы следующий запрос к API начинался со следующего сообщения.
2. `while True` (бесконечный цикл): Бот должен работать постоянно, пока его не остановят вручную. Этот цикл превращает скрипт в демон-процесс, который живёт в фоне и ждёт событий.
3. `try/except`: Сеть нестабильна: интернет может моргнуть, сервер Telegram — временно ответить ошибкой 502, токен — оказаться невалидным. 
4. Проверка `updates.get("ok")` and `updates.get("result")`: Telegram API всегда возвращает JSON с полем `"ok"`: `true`/`false`. Мы проверяем успешность запроса и наличие данных ("result").
5. `for update in updates["result"]`: API может прислать сразу несколько сообщений (если пользователь
отправил их подряд, пока бот ждал). Цикл for гарантирует, что каждое событие будет обработано по очереди.
6. `time.sleep(1)`: Если сообщений нет, бот будет «стучаться» к серверу Telegram слишком часто. Пауза в 1 секунду снижает нагрузку на сеть и экономит ресурсы процессора.
